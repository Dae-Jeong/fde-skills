01 · Layer 1

매크로 아키텍처 Flow — 공식 장부와 야전 장부의 분기

같은 오더가 세 개의 레인을 동시에 흐른다. 공식 시스템은 사후에, 일괄로, 요약해서 기록되고, 실제 의사결정은 Shadow IT 레인에서 먼저 일어난다. 빨간 배지는 두 장부가 다시 맞춰지는(=어긋나는) 동기화 지점이다.

① 수주 변경 → ERP
구두·카톡 수락 후 1~3일 뒤 입력. 그 사이 MRP는 옛 수량으로 자재를 계산한다.
② 재고 엑셀 → ERP
입고·사급출고가 사후 일괄 처리되어 ERP 재고가 음수·과다로 흔들린다. 진짜 재고는 자재담당 엑셀에.
③ 작업일보 → MES
실적이 익일~주말에 몰아서 입력된다. 셋업·대기·재작업 시간은 이 과정에서 사라진다.
④ 불량·특채 → QMS
특채는 카톡 승인으로 끝나고 기록되지 않는다. 수율은 월말에 투입·출하로 역산된다.

03 · Layer 2

3대 페르소나 Deep Dive — 금요일 오후 긴급 PO 변경

시나리오 — 금요일 16:30, 고객사 A(가상) 구매팀 메일: "다음 주 화요일 납품분 2,000ea → 3,500ea 증량, 납기 하루 당김(월요일) 가능할까요?" 자재는 약 1,500ea분, 도금은 외주(협력사 B), 사출기 3호기는 다른 오더로 금형이 걸려 있다.
금 16:30고객 메일 · 영업 → 사장님 전화
금 16:45사장님 "무조건 된다고 해" 구두 수락
금 17:00팀장 긴급회의 · 다른 오더 밀기 결정
금 17:40협력사 B 전화로 토요일 도금 사정
토 08:00특근 · 단도리 · 땡겨치기 생산
월 10:00ERP·MES 사후 입력, 일보 몰아쓰기
사장님 (Owner)평가 지표: 매출 · 거래처 관계 · 현금흐름
속마음
"A 물량 놓치면 내년 단가 협상 끝이다. 안 되는 게 어딨어, 일단 된다고 해."
실제 행동
  • 전화로 즉시 수락, 메일 회신은 영업에 맡김
  • ERP 수주 수정 지시 없음
  • 월요일 아침 "어떻게 됐어?"만 확인
데이터 왜곡
ERP 수주는 2,000ea·화요일 그대로 → MRP·캐파 계산이 틀린 채 주말이 지나간다. 다른 고객 납기 지연은 보고되지 않는다.
WIIFM — 이 사람이 원하는 화면
금요일 16:40에 "3,500ea 월요일 납품 시 밀리는 오더·필요 특근·자재 부족분"을 5분 안에 보는 수락 전 영향 카드.
생산관리팀장 (Manager)평가 지표: 납기 준수율 · 특근비 · 재고
속마음
"자재 1,500개분인데… 창고 구석 버퍼 쓰고, B사에 사정하고, C 오더는 다음 주로 밀자. 위에는 다 된다고 해야지."
실제 행동
  • 비공식 버퍼 재고 투입
  • 다른 작업지시 순서 변경(땡겨치기)
  • 외주 긴급 발주는 전화, PO는 월요일
  • 특근 편성 카톡 공지
데이터 왜곡
MES 작업지시 순서·일자가 실제와 불일치. 버퍼 재고는 장부에 없어 다음 MRP에서 결품이 터진다. 밀린 C 오더는 숨겨진다.
WIIFM
자재 가용성 + 밀리는 오더 영향 자동 계산, 위로 보고할 근거 한 장. "안 됩니다"를 숫자로 말할 수 있게.
반장 · 작업자 (Operator)평가 지표: 일 생산수량 · 불량 건수
속마음
"단도리 또 바꿔? 금형 교체 한 시간인데 실적엔 안 잡혀. 바리 나오면 사상으로 갈고… 일보는 월요일에 몰아 쓰지 뭐."
실제 행동
  • 금형 교체(단도리) 후 초물 검사 생략
  • 바리·찍힘은 야스리·빠우로 현장 수정
  • 작업일보 월요일 일괄 작성(가라)
데이터 왜곡
셋업·재작업 시간 누락 → OEE·UPH 과대. 재작업품이 양품으로 집계 → 수율 과대. 초물 검사 기록은 사후 작성.
WIIFM
태블릿 1탭 입력(시작·정지·불량), 특근·재작업 시간이 본인 실적으로 인정되는 구조. 입력이 손해가 아니어야 한다.
충돌 지점 — 사장님은 "된다"를, 팀장은 "됐다고 보이는 숫자"를, 작업자는 "손해 안 보는 기록"을 원한다. 세 인센티브가 모두 공식 장부를 늦게·좋게 기록하는 방향으로 수렴한다. FDE는 누가 거짓말하는지 찾지 말고, 정직하게 기록하는 것이 각자에게 이득이 되는 입력 지점을 설계한다.

04 · Layer 4

정통 이론 4선 vs 야전 리얼리티

이론은 정답이 아니라 현장이 어디서 어긋나는지 재는 자다. 공식 → 필요한 입력 → 현장 오염 → 숫자가 하는 거짓말 → 이론을 되살리는 최소 정직 데이터 순서로 본다.

① OEE / TPM설비종합효율 · 전원참가 생산보전 — Stage 3
OEE = 가용률 × 성능률 × 양품률
가용률 = (계획가동 − 정지시간) / 계획가동
성능률 = (이론 C/T × 생산수량) / 실가동시간
양품률 = 양품수 / 생산수량
필요 입력정지 사유·시간(고장·셋업·대기), 이론 C/T, 생산수량, 양품수
현장 오염
  • 단도리·데마찌는 "정지"로 안 적음 → 가용률 과대
  • 가라 실적으로 생산수량 맞추기
  • 시야게·빠우 재작업품이 양품으로 → 양품률 과대
85% → 55%보고 OEE vs 정지 사유를 실측하면 드러나는 수준(가상 예시)
최소 정직 데이터: 설비별 시작/종료 + 정지사유 5코드(고장·단도리·자재대기·품질·기타). 이것만 있어도 가용률은 진짜가 된다.
② TOC / DBR & Little's Law제약이론 · Drum-Buffer-Rope · 대기행렬 — Stage 1·3
WIP = Throughput × Lead Time (L = λW)
DBR: 병목(Drum) 속도로 투입(Rope) 통제,
병목 앞에만 시간 버퍼(Buffer)
필요 입력병목 공정 식별, 공정간 WIP 수량, 투입·완료 시각
현장 오염
  • 밀어내기: 가동률 KPI 때문에 모든 공정이 최대로 돌림 → WIP 산더미
  • 병목이 매일 바뀜(외주 도금·열처리 대기)
  • 땡겨치기로 투입 순서 역전 → 리드타임 측정 불가
가동률 ↑ 납기 ↓모든 공정 가동률이 높은데 납기는 밀리는 역설
최소 정직 데이터: 공정간 WIP 일 1회 카운트 + 이번 주 병목 1개 지정. Little's Law로 리드타임을 역산해 납기 약속의 근거로 쓴다.
③ MRP / Backflush & ABC자재소요계획 · 사후 자재차감 · 활동기준원가 — Stage 2
순소요 = 총소요 − 가용재고 − 입고예정 + 안전재고
Backflush 차감 = 완성수량 × BOM 단위소요 × (1+로스율)
ABC 원가 = Σ (활동 사용량 × 활동 단가)
필요 입력정확한 BOM·로스율, 실시간 재고, 적시 실적, 활동별 시간
현장 오염
  • E-BOM ≠ 실제 사용 자재(대체자재·로스 미반영)
  • 실적 지연 입력 → Backflush 지연 → 재고 음수
  • 사급자재가 외주처에 있는데 장부에서 사라짐
  • 원가는 매출 비례 배부 → 단도리 많은 소량 품목 적자 은폐
재고 −320ERP 재고 음수 + 창고에는 실물 존재
최소 정직 데이터: A급 자재 20품목 주간 실사 + 품목별 로스율 1컬럼 + 외주처 재고 월 1회 확인.
④ 6σ SPC / COQ & Mass Balance통계적 공정관리 · 품질비용 · 질량보존 — Stage 4
Cpk = min(USL − μ, μ − LSL) / 3σ
COQ = 예방 + 평가 + 내부실패 + 외부실패
투입 = 양품 + 불량 + 스크랩 + 재공 + 로스
필요 입력원본 측정값 시계열, 불량·재작업 비용, LOT별 투입/산출 중량·수량
현장 오염
  • 측정값 사후 작성 → 규격 중앙값에 몰림 → σ 과소
  • 특채 출하분이 양품으로 집계
  • 현장 재작업 공수가 COQ에 없음
  • 투입-산출 차이를 전부 "로스"로 뭉뚱그림

05 · Layer 3 — Tier 1

제조업 스키마 용어 사전 (Schema Terms)

시스템·표준 문서에 나오는 정식 개념. 데이터 모델을 설계할 때의 기준이지만, 각 용어마다 현장이 다르게 쓰는 함정이 있다.

용어정의대표 테이블 · 필드현장 함정 · 흔한 오해
BOMBill of Materials · 자재명세서제품 1단위를 만드는 데 필요한 자재·반제품의 계층 구조와 소요량.bom_item(parent_item, child_item, qty_per, loss_rate, rev)설계 BOM(E-BOM) ≠ 생산 BOM(M-BOM). 대체자재·로스율 미반영, 개정 이력 없이 덮어쓰기 → Backflush 재고 오차의 1순위 원인.
Work Order작업지시 · W/O품목·수량·공정(라우팅)·설비·일자를 지정한 생산 실행 지시 단위.work_order(wo_no, item, plan_qty, line, plan_date, status)현장에서는 지시를 쪼개거나(분할 생산) 합쳐서(땡겨치기) 실행. 상태가 '진행중'으로 수주일째 방치, 실적일 < 계획일 역전.
Subcontracting외주 · 임가공공정 일부(도금·열처리·사출 등)를 협력사에 위탁. 자재를 제공하면 사급(무상/유상).subcon_order(vendor, process, qty), material_issue(to_vendor, lot)협력사에 나간 사급자재가 장부에서 증발. 외주 불량의 책임 소재 불명확, 반입 수량 ≠ 반출 수량(로스) 미대사.
LOT로트 · 생산/입고 묶음동일 자재·조건·시간대로 생산·입고된 추적 단위. 추적성(Traceability)의 핵심 키.lot(lot_no, item, qty, parent_lot, created_at)LOT 혼입(섞임), 수기 라벨, 분할·병합 시 계보 단절 → 클레임 시 역추적 불가. 현장은 LOT보다 "몇 박스째"로 기억.
Yield수율 · FPY양품 / 투입. 직행률(FPY, 재작업 없이 한 번에 통과)과 최종수율은 다른 지표.yield = good_qty / input_qty, fpy = first_pass_good / input_qty재작업 후 양품을 FPY에 포함, 분모를 '투입'이 아닌 '생산'으로 계산, 특채품을 양품 집계 → 수율 98% 착시.
초·중·종물 검사First / Mid / Last Article작업 시작(셋업 직후)·중간·종료 시점의 샘플을 검사해 공정 이상을 조기에 잡는 절차.inspection(type, lot_no, item, measured_value, usl, lsl, judge, inspector, at)측정값 대신 OK 체크만, 시각은 사후 일괄 기록. 단도리 직후 초물 검사 생략이 불량 대량 발생의 전형 경로.
CAPA / UPH시정·예방조치 / 시간당 생산량CAPA: 불량 원인 분석 → 시정·예방 대책 → 효과 확인. UPH: Units Per Hour, 라인 생산성 지표.capa(issue, root_cause, action, owner, verify_date) / uph = good_qty / run_hoursCAPA가 고객 제출용 문서로만 존재(효과 확인 공란). UPH 분모에서 셋업·대기를 빼서 생산성 부풀림.
FIFO선입선출먼저 입고된 자재·LOT를 먼저 사용·출하. 유효기한·변질·재고 노후화 방지.inventory_txn(lot_no, item, received_at, issued_at, location)실제로는 앞 칸 자재부터 집는 LIFO. 유효기한 레진·부자재가 랙 안쪽에 방치, 장부상 FIFO와 실물 출고 순서 불일치.
FDE 적용 — 고객사 스키마를 받으면 이 8개 개념의 실제 테이블·컬럼명을 먼저 매핑하고, "함정" 열의 항목이 데이터에서 실제로 보이는지 SQL 한 줄씩으로 확인한다(예: actual_date < plan_date 비율, 재고 음수 품목 수).

현장 은어 사전 (Field Slang)

현장 인터뷰에서 실제로 들리는 말. 다수가 일본어 잔재다. 은어마다 데이터에 남는 흔적을 적는 것이 핵심 — 그것이 더티 데이터 시드의 원천이다.
