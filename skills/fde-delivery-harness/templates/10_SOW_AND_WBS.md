## 2. 과업 범위 기준 관리 5대 원칙 (`Baseline Governance Rules`)

1. **일정 부족 시 내재화 기간 축소 금지**: 일정 충돌 발생 시 **승인된 내재화 길이(2~4주, 기본 4주)를 먼저 깎지 않으며**(줄일 때도 `쓴다·고친다·버틴다·넘긴다` 네 활동을 합칠 뿐 빠뜨리지 않음 `[사실: 덱 p.24]`), 팀장 확인 및 WBS 변경 기록(`CR-###`)을 통해 과업 범위를 조정하거나 계약 기간을 연장한다.
2. **정형 자동화(80%)와 예외 승인(20%) 분리**: 100% 무인 처리를 가정하지 않으며, 비정형·오류 데이터는 예외 보정 및 관리자 승인 구간을 거쳐 반영한다.
3. **선행 진단 기반 중복 질문 제한**: 선행 PI 진단이 있는 만큼만 다시 물으며, 미확인 영역(승인권자·예외 기준·원천 산식) 확인에 집중한다.
4. **기한 초과 보류(`Hold`) 출구 규칙**: 합의 기한까지 `D-###`/`B-###`가 해소되지 않으면 `CR-###`를 통해 해당 모듈을 현 단계 범위에서 제외하거나 조건부 인수로 전환한다.
5. **작업시간 절감 산식의 법적 한계 명시**: 작업시간 절감 추정치(`횟수 × 인원 × 단축시간`)의 인건비 환산액은 현금 절감이나 매출 증가를 보증하지 않으며, 최종 성과는 고객 원천 데이터 대조 후 인용한다.

## 4. 계약 기간 구간표 및 역산 WBS (`Backward-Scheduled WBS: L1 ~ L3`)

> **계약 기간별 표준 구간표 (Flowpass 기준)**: 내재화 길이는 **과업 유형 표(`[사실: 덱 p.29]`)를 1차 기준**으로, 같은 유형 안에서 계약 주수·월 단위 업무 유무(월 업무 있으면 4주 / 없으면 8주 미만 2주·8~11주 3주·12주 이상 4주 `[사실: 덱 p.24]`)로 2/3/4주를 확정한다(본 템플릿 기본 상정 = 재구축형 20주 이상·4주). 확정값은 아래 WBS Step 5 행에 **"승인 내재화 길이"로 1회만 기재**하고 `00_`·`40_`·`50_`은 그 값을 참조한다. 전체 계약 주수에서 **`[승인 내재화 길이(2~4주) + UAT(1~2주)]`를 종료일로부터 먼저 차감**하여 **UAT 착수 시점 = 종료일 - (승인 내재화 길이 + UAT 길이)** 로 두고(예: 4주+2주 = 종료 6주 전, 2주+1주 = 종료 3주 전), 앞단 `[인계·킥오프(1주) + Discovery(1~2주) + 실행계획(1주)]`을 뺀 **남은 기간 전부**를 Build 기간으로 산정한다(중간보고 횟수 = `Build 주수 ÷ 5주 올림`, Build 4주 미만 시 주간 시연으로 대체, **Build ≤ 0이면 범위 축소 또는 기한 연장 재합의**).
